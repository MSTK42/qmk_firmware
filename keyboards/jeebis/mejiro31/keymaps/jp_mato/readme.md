# Mejiro31: mato式 + メジロ式 hybrid

Mejiro31 用の追加キーマップです。英語・日本語とも O24 の従来モード、メジロ式、その既存レイヤーを保持し、mato式を明示的に選べるようにします。既存の `jp_default` と他のプリセットは変更しません。起動時は従来の O24 です。

ビルド:

```sh
qmk compile -kb jeebis/mejiro31 -km jp_mato
```

## モードの選び方

位置はキーボードを上から見た向きです。「上段」「下段」は文字キーの 2 段を指します。

| 現在 | 操作 | 結果 |
|---|---|---|
| O24 | 下側親指の左端と右端（従来の `O24_KEY1` + `O24_KEY4`）を保持して SYSTEM を開き、**右手上段の一番左**を押す。その後すべてのキーを離す | mato式へ |
| mato式 | **左外端の上段**を押し、すべてのキーを離す | O24 へ |
| mato式 | **左外端の下段**を押し、すべてのキーを離す | メジロ式へ |
| mato式 / O24 / メジロ式 | 従来どおり **右外端の上下 2 キーだけ**を同時押し | メジロ式との往復 |

右外端によるメジロ式からの復帰先は、直前のキーボードモードです。mato式を選択した後は mato式に戻ります。O24 に戻すには mato式の左外端上段を使います。SYSTEM の入口は従来未割当だった位置に追加しています。

選択中のモードは RAM 内だけに保持します。USB 再接続 / リセット後は O24 に戻り、mato式のための EEPROM 項目や書込みは追加しません。既存初期化処理の EEPROM 動作はそのままです。

mato式の最初の選択時は日本語入力を要求します。上側親指の既存の英数 / かなキーで選んだ言語は mato式側で保持し、メジロ式との往復時に復元します。O24 側の言語選択は別に保存し、O24 に戻る際に復元します。英数 / かなの切替も、文字キーをすべて離してから操作してください。

モード要求は、物理キーが全部離され、従来の FIFO と修飾状態が解放された後に反映します。mato式からの退出要求時には未確定文字を取消し、保持中のキー / 修飾を解放します。切替途中のキー入力も次モードに持ち越しません。

## mato式の配置

[作者の記事「mato式」](https://note.com/mato_kb/n/nf57efe5d6ca0) にある 2024-04-01 更新の現行配置を、2026-10-23 に 7 枚の図で確認しました。図の内訳は **5 層、修飾コンボ、任意の撥音拡張**です。作者の 24 キーを Mejiro31 の中央 20 文字キーと下側親指 4 キーへ配置しています。

基本層:

```text
             左手                           右手
        L   W   K   R   P             Tab  U   O   Y   -
        H   S   T   N   M             BS   A   E   I   ,

          半全     Space                  Enter     MO1
          [MO2]    [MO3]                  [MO4]
```

右下親指 `MO1` を保持:

```text
        X   V   G   F   Q             Esc  U   O   Y   /
        B   Z   D   C   J             Del  A   E   I   .

          Shift    Space                  無効      [MO1]
                   [Shift]
```

数字 / 記号は MO2、カーソル / Ctrl+Z/X/C/V は MO3、F1〜F20 は MO4 です。全 5 層の位置とキーは出典付きの `mato-source.json`、その機械変換は `mato_tables.c` にあります。JIS の記号コードを直接使うため、OS のキーボード配列は日本語 JIS を前提にします。mato式の記号を従来の O24 / JIS 変換へ再度通しません。

基本層 / MO1 では次の縦 2 キーで修飾を保持します。

| 左手の列（左から） | 修飾 | 右手の列（左から） | 修飾 |
|---|---|---|---|
| 1 | Shift | 2 | Ctrl |
| 2 | GUI / Windows | 3 | Alt |
| 3 | Alt | 4 | GUI / Windows |
| 4 | Ctrl | 5 | Shift |

両手で同じ修飾を保持した場合や Ctrl+Z/X/C/V と重ねた場合も、残っている側が離されるまで修飾を維持します。メジロ式の速記同時押しは従来の処理をそのまま使います。

## 作者の図から決められない部分と今回の実装

作者の記事の配列図から入力位置を確認しましたが、参照した資料からは QMK ソースやタイミング条件を確認できませんでした。以下は本キーマップでの実装判断です。

| 項目 | 今回の動作 |
|---|---|
| 半全 / Space / Enter と MO2 / MO3 / MO4 | 単独で 175ms 未満に離すと文字、175ms 以上または別キーの押下で保持側 |
| MO1 | 押下直後に有効、離すと解除 |
| Shift Space / Shift Enter の二重凡例 | 単独短打は Space / Enter、保持または別キーとの併用は Shift |
| 縦 2 キーの修飾コンボ | 同じ仮想層で 2 キー目が 50ms 未満に押された場合に成立。50ms ちょうどから通常キー |
| 修飾の解除 | コンボの最初のキーを離したとき。残るキーは文字として出さない |
| コンボの対象層 | 基本層と MO1 のみ。数字 / カーソル / F キー層では成立させない |
| 左右の修飾コード | 左 Shift / Ctrl / Alt / GUI を使い、重複保持を参照数で管理 |
| 図の空欄 | 無効キー。透過と記されたキーだけ下の有効層へ戻る |
| 複数層が有効 | 層番号の大きい層を優先し、透過セルは下の有効層へ戻る |
| 任意の撥音拡張 | 作者自身が未使用と述べているため含めない |
| 電源投入時 | O24。mato式は明示的に選択する |

50ms の候補待ち中でも、次の別キーの押下や修飾の解放時には先の文字を押下順に確定します。層をまたいで離しても、押した時点のキーコードで解放します。長く保持した通常キーは OS のリピートに対応します。

## 検証

```sh
python3 util/test_mejiro31_mato.py
```

C99 コンパイラ `cc` / `gcc` / `clang` を利用します。別のコンパイラは `--cc PATH` または `MATO_CC` で指定できます。テストは `.build` 内の一時ディレクトリを使い、終了時に削除します。

- 出典 JSON と生成済み 5 層 / 8 コンボ表の一致。
- ファームで使う実際の `mato_engine.c` を実行。コンボ 49 / 50 / 51ms、層をまたぐ文字順、修飾の先離し、二重 Shift、Ctrl ショートカットの重複、10 万回のランダムな押下 / 解放、全解放 / reset 後の残留を確認。
- 実際のラッパーと、従来ファームから抽出した変更なしの右端切替関数を実行。24 キーの物理位置、O24 起動、入口の全解放待ち、メジロ式への受渡し、言語復元、未確定文字の取消し、メジロ式内部の強制 QWERTY 経路を確認。
- CI ではこのホストテストに加え、`jp_mato` と従来 O24 プリセットの QMK ファームをそれぞれビルド。

ホストテストでは USB / マトリクス / IME をスタブに置き換えています。実機の押下感覚、USB 接続先の JIS 設定、各 IME の言語切替反応は実機確認が必要です。mato式の学習や実機での使いやすさをホストテストの成功だけで評価していません。
